# 3. Правила разработки

Это **обязательные правила** всего проекта. Их нужно соблюдать на каждом этапе.

---

## 1. Никаких фейковых данных

### Запрещено:

- Создавать вымышленные отзывы и выдавать их за реальные.
- Придумывать клиентов, записи, мастеров, статистику, выручку и рейтинги.
- Показывать фиктивные записи в production-интерфейсе.
- Подменять неработающие запросы к БД локальными массивами.
- Использовать hardcoded значения вместо реальных данных.
- Подставлять фиктивные ответы API.
- Показывать фиктивные уведомления об успехе.

---

### Разрешено:

- Тестовые данные **только в**:
  - Изолированных автоматических тестах
  - Seed-файлах для локальной разработки
  - Специально обозначенном демо-окружении

> Эти данные **не должны попадать в production**.

---

## 2. Качество кода

### Требования:

- Используй **строгую типизацию TypeScript**.
- Не используй `any` без обоснованной необходимости.
- Избегай огромных компонентов и файлов с логикой.
- Разделяй: UI ↔ бизнес-логика ↔ доступ к данным ↔ инфраструктура.
- Создавай **переиспользуемые компоненты**.
- Обрабатывай: `loading`, `error`, `empty`, `success` состояния.
- Убирай неиспользуемый код, импорты и зависимости.
- Не отключай ESLint, TS strict mode или тесты ради устранения ошибок.
- Не скрывай ошибки через пустые `catch`.
- Не дублируй бизнес-логику в нескольких местах.
- Не используй `setTimeout` в браузере как механизм гарантированной отправки напоминаний.
- Не оставляй TODO для критических функций, выдавая их за реализованные.

---

## 3. Обучение разработке

Цель — чтобы ты **не был человеком, который только копирует** сгенерированный код. Ты развиваешься как программист.

### Требования к объяснениям:

- Объясняй важные архитектурные решения и нетривиальные участки кода **в комментариях**, где они действительно полезны.
- **Не комментируй** каждую очевидную строку.

---

### Отчёт по этапу должен включать:

1. Что реализовано.
2. Как это работает.
3. Какие файлы созданы или изменены.
4. Какие решения приняты и почему.
5. Какие проверки выполнены.
6. Какие настройки нужно выполнить вручную.
7. Что осталось незавершённым.
