# 8. Онлайн-запись: Booking Flow

Создай последовательный и удобный **booking flow**.

---

## 1. Шаг 1: Выбор мастера

Показывай:

- [ ] Имя и фото
- [ ] Описание
- [ ] Специализация (если есть)
- [ ] Услуги, реально выполняемые мастером
- [ ] Рабочие дни и часы
- [ ] Ближайшее доступное время
- [ ] Начальные цены услуг

Если мастер свободен только в дальнем будущем → сообщай корректно.

---

## 2. Шаг 2: Выбор услуг

### Категории по умолчанию:

- [ ] Стрижка
- [ ] Борода
- [ ] Комплексы
- [ ] Скидки
- [ ] Новинки

> Владелец может создавать / редактировать / сортировать / удалять категории.

### Услуга содержит:

- [ ] Название
- [ ] Описание
- [ ] Категория
- [ ] Фотография
- [ ] Цена
- [ ] Длительность (минуты)
- [ ] Активность
- [ ] Доступные мастера
- [ ] Порядок отображения

### Ограничения:

- Максимум **3 услуги** в одной записи.
- Показывай промежуточную стоимость и суммарную длительность.
- ❌ Не разрешать выбрать скрытую / удалённую / недоступную услугу.
- Для комплексов и скидок — понятные правила расчёта.  
  ❌ Не применять скидку дважды.
  ❌ Не придумывать процент скидки, если он не задан.

---

## 3. Шаг 3: Выбор даты и времени

Используй календарь, `date-fns`, при необходимости `date-fns-tz`.

### Доступность рассчитывается с учётом:

- Рабочего расписания барбера
- Перерывов
- Выходных и отпусков
- Индивидуальных изменений расписания
- Длительности выбранных услуг
- Уже существующих активных записей
- Минимального времени до записи
- Максимального горизонта предварительной записи
- Часового пояса барбершопа

### Интерфейс:

- Можно использовать разбивку: утро / день / вечер — как дополнительную навигацию.
- ❌ Не заменяй этим точные временные слоты.
- Занятые / недоступные слоты — **явно обозначены**, не выбираются.
- Полностью занятые дни можно отключать.

---

## 4. Шаг 4: Подтверждение и создание

Перед подтверждением покажи:

- [ ] Мастера
- [ ] Услуги
- [ ] Цены
- [ ] Длительность
- [ ] Дата и время
- [ ] Общая стоимость
- [ ] Адрес
- [ ] Правила отмены
- [ ] Выбранные настройки уведомлений

### Оплата:

- Только **в барбершопе**. Онлайн-оплату **не реализовывать**.

---

## 5. Подтверждение создания

- Покажи **реальный ID записи** и её **текущий статус**.
- ❌ Не показывать успех, пока БД не подтвердит создание.

---

## 6. Критически важная защита бронирования

Реализуй защиту на **серверной стороне** и на уровне **PostgreSQL**.

### Требования:

- ✅ Два клиента не могут забронировать пересекающееся время.
- ✅ Проверка доступности + создание — защищены от одновременных запросов.
- ✅ Повторная отправка не создаёт дубликаты.
- ✅ Ошибка сети не приводит к повторному бронированию.
- ✅ Отмена освобождает слот.
- ✅ Изменение расписания не создаёт скрытых пересечений.
- ✅ Время начала/окончания вычисляется доверенной серверной логикой.
- ✅ Клиент не может подменить длительность, цену, статус или владельца через DevTools.

### Используй:

- Транзакции
- Exclusion constraints (PostgreSQL range types)
- Блокировки
- RPC-функции / серверные функции для атомарного создания записи

❌ Не полагаться только на проверку слота в React.
