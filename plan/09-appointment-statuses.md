# 9. Статусы записей

---

## 1. Список статусов

| Статус        | Описание                        |
|---------------|---------------------------------|
| `pending`     | Ожидает подтверждения           |
| `confirmed`   | Подтверждена барбером           |
| `in_progress` | Обслуживание началось           |
| `completed`   | Обслуживание завершено          |
| `cancelled`   | Запись отменена                 |
| `no_show`     | Клиент не пришёл                |

---

## 2. Переходы статусов

### Основной поток:

```
pending → confirmed → in_progress → completed
```

### Дополнительные переходы:

- **Отмена** (`cancelled`) — допустима на любом этапе, если правила бизнеса это разрешают.
- **Неявка** (`no_show`) — устанавливается барбером, если клиент не пришёл.

### Ограничения:

- ❌ Клиент не может установить `completed` или `no_show`.
- ❌ Истёкшее время записи **не переводит** автоматически в `completed`.
- ✅ История переходов сохраняется с датой, инициатором и причиной.

---

## 3. Использование данных

- В аналитике учитываются **только `completed`** записи.
- Если запись содержит несколько услуг — **не дублируй** общую стоимость.
- Учитывай часовой пояс при фильтрации по датам.
- Храни денежные значения с **точностью до копеек** (например, `numeric(10,2)`).

---

## 4. Пустые состояния

Если данных недостаточно — показывай **корректный empty state**, а не график с придуманными значениями.
