# 23. Стратегия тестирования

---

## 1. Unit Tests (Vitest)

Проверь:

- [ ] Расчёт длительности
- [ ] Расчёт общей стоимости
- [ ] Правила скидок / комплексов
- [ ] Переходы статусов записей
- [ ] Фильтрацию записей
- [ ] Граничные случаи работы с датами (timezone, DST, границы месяцев)

---

## 2. Integration Tests

Проверь:

- [ ] Создание записи
- [ ] Подтверждение записи
- [ ] Перенос записи
- [ ] Отмену записи
- [ ] Освобождение слота
- [ ] Создание записи барбером
- [ ] Сохранение исторических цен
- [ ] Права доступа (RLS)
- [ ] Сохранение истории статусов
- [ ] Поведение при ошибках БД

---

## 3. E2E Tests (Playwright)

### Основные пользовательские сценарии:

1. Клиент входит в аккаунт
2. Выбирает мастера
3. Выбирает услуги
4. Выбирает свободный слот
5. Подтверждает запись
6. Видит созданную запись в профиле
7. Барбер подтверждает запись
8. Барбер начинает и завершает обслуживание
9. Завершённая запись учитывается в аналитике
10. Клиент переносит или отменяет запись
11. Повторный запрос не создаёт дубликат
12. Пользователь не может получить доступ к чужим данным
13. **Два параллельных запроса не создают пересекающиеся записи**
14. Напоминание не отправляется дважды
15. Ошибка внешнего сервиса не ломает создание записи

---

## 4. Требования к тестам

- Используй **изолированное тестовое окружение** и тестовые аккаунты
- ❌ Не выполняй destructive-тесты на production
- Проверяй не только компиляцию, а **работу функций**
